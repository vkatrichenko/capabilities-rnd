hops: three-layer secrets defense, and it measurably works

An advisory local hook (scripts/pre-commit) → an agent-time block (PreToolUse → block-secrets.sh) → an unconditional CI gitleaks gate with a tuned, false-positives-only allowlist (.gitleaks.toml). This matches the 2026 industry consensus layering exactly. The worktree scans clean under its own config.

Partial credit elsewhere

Action needed now (barley owners): rotation check Still in HEAD: 2× GitLab runner-registration tokens in committed VCR cassettes (GR1348…) and 1× Slack bot token in reports/smoke.html. In history (removal ≠ revocation): 13 Slack tokens hardcoded in Terraform across dev and prod (2024-12 → 2025-07), one full service-account private key. barley’s own June audit additionally found a production RDS password, a LangSmith key and an OAuth secret in local .claude/settings.local.json allow-patterns — rotation status unknown.

How the leaks happen — the vectors are AI-SDLC-shaped

  • Recorded test cassettes. barley scrubs cassettes — headers properly, bodies via a key denylist (access_token, Zoom fields, emails). GitLab returns the runner token under runners_token — not on the list → committed verbatim. Denylist scrubbing fails open on every new API field.
  • Committed artifacts. A test report (smoke.html) embedding a live bot token.
  • IaC values pasted inline. Slack tokens in Terraform locals for 8 months.
  • Agent permission allow-patterns as a secrets store. Live credentials inside Claude settings allow-lists — an AI-native vector that no code scanner sees.

Not one of the 24 real-format leaks was in application source code. Defense-in-depth is what turns “the scrubber has a hole” into a non-event — hops has the backstop, barley does not.

Every stdio MCP config executes a mutable-version third party with the developer’s (and the agent’s) local privileges — the AI-SDLC equivalent of curl | bash at every session start. CSA and the OWASP Agentic Top 10 (ASI01) both name exactly this “rug-pull” window; the AWOS audit currently passes it.

Systemic pattern across both audited repos: detector scoping assumptions (root-only paths, directory conventions, excluded dirs) produce false verdicts in both directions. Report upstream to the AWOS audit owners.

The thesis this evidence supports At ~80% AI-authored code, the industry answer (Anthropic) is not more human review — it is deterministic gates, narrow-scope review agents with mandatory evidence, and logged accountability. BarHopping shows both sides of that bet in one org: hops with the first layer installed (2 leaks, both pre-gate, loop closes findings in days) and barley without it (22 leaks, 3 live in HEAD, its own audit’s rotation advice unactioned). The gap is the capability story.

Method & next steps

Same tool and ruleset across repos (gitleaks 8.24.3 — the version hops’ own CI pins); findings deduped, classified in-HEAD vs history-only, manually reviewed with values masked; no credential tested for validity; every audit claim re-verified against the repo by hand. All repos read-only, verified untouched. Full trail: methodology/log.md, findings in research/ — every number in this report has a file behind it.

Next (Phase 2): implement the hops-scoped items above (dev-only, AWOS workflow), capture before/after evidence per item; then Phase 3 generalizes the portable checks and the measured deltas into the publication.
