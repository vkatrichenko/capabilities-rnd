## The method, stated plainly (this is what the report's "How we score" tab renders)

1. **One list for every repository.** The same 23 controls, grouped into the five areas of this
   capability, derived from the AWS Startup Security Baseline plus the container/AI additions named
   in `../sources/cloud/benchmarks-and-standards.md`. The list is not ours; the verdicts are.
2. **Three verdicts.** `pass` = 1 point: the control is in place *and its ownership is explicit* —
   declared in code, or provided centrally by a named owner — so it cannot silently disappear.
   `partial` = ½: present in one environment but not another, enabled by hand where a person could
   disable it, or present with a weaker mechanism than the standard asks. `fail` = 0: absent.
3. **`na` is excluded from the denominator**, never scored as zero. A repository with no database is
   not marked down for failing to encrypt one. This is why denominators differ (19 for core-infra,
   21 for hops-infra, 6 for the sowinsights app) and why small repositories are not comparable to
   large ones.
4. **Coverage = awarded ÷ applicable.** Group scores use the same arithmetic over that group's
   controls only.

**Judged, not measured** — and the limits follow: two careful reviewers could differ on individual
cells; `partial` is blunt (a shared encryption key and a dev-only gap both score ½); it is a snapshot
at the refs below. Each verdict carries its evidence string, so a disagreement can be about a specific
cell rather than the number. The intended end state is the proposed `infrastructure-security` audit
dimension (`../findings/awos-infra-coverage.md`), producing this automatically from a repository tree
plus a Prowler collector.

**Account context matters to the scoring.** `941000539201` is a *member* account of the organization
whose management account is `060183668755`, run by the IT department. Human access is AWS SSO with
role assumption; the root user has no access keys. Two organization CloudTrail trails and an AWS Config
StackSet are pushed down from that management account. Controls owned there are scored on whether they
are *in place and attributable*, not on whether a project repository declares them — scoring a project
down for not re-declaring an org-managed trail would be wrong.
